# Expertise: API Critic

Curated playbook of what this role has learned. **Not a log.** Edit existing entries when a new observation refines or supersedes them; add new entries only when truly new ground is covered; remove entries that no longer earn their place. Every entry earns its line by tracing to a real failure or repeated success, and follows the entry shape (lead + body + anchor) in mental-model rule 11.

## Patterns to reach for

- **Walk the new surface as a user typing the class name and hitting tab; read the resulting tooltip.** Discoverability cliffs (a user expecting `Class.from_networkx` and finding only `_partition` / `_variable_sweep` / `_tags` siblings) and signature-tooltip lies (a classmethod that lifts list-shaped parameters into the signature while leaving required singleton companions buried in `**kwargs`) disappear from code-only diff review but surface immediately in tab-completion simulation. Make this the first-pass check for any new public surface. *Learned:* hiveplotlib #46 Workstreams F (no discoverability stub for `HivePlotMatrix.from_networkx_*` siblings) and G (incomplete signature lift on `from_networkx_variable_sweep` caught planning-mode before code).

- **When a plan proposes multiple new "modes" for one agent, check whether each mode has independent function or is a parameter switch.** A real mode differs in inputs, outputs, or decision shape (`initial-plan` produces a new file; `amend-plan` reads an existing file and edits its amendments section). A parameter switch reuses an existing mode's function with a different consumer or path; collapse it into the existing modes rather than coining a sibling. *Learned:* `orchestrator-on-emergent-work` planning review collapsed `harness-meta` mode into a consumer parameter on the two existing modes.

- **After a planning-mode collapse of N modes into N-1, post-impl review must sweep for residual mentions of the dropped mode name.** Treat the post-impl pass as the replace-and-sweep audit for the dropped name. The Modes section closes cleanly, but the dropped name often survives in parenthetical lists, Output descriptions, error messages, or example invocations because those sections describe behavior rather than enumerate modes. Grep the whole file before declaring clean. *Learned:* `orchestrator-on-emergent-work` post-impl — `orchestrator.md:34`'s Output section retained "harness-meta work" as a work-category label, inventing a parallel taxonomy in a file that committed to two modes.

- **Sweep adjacent surfaces (roadmap docs, vision pages) after tearing out a public API; they don't track the implementation grep.** Roadmap / vision / future-work pages describe a promised capability by *intent*, not by *name*, so the source/autodoc/notebook grep doesn't reach them. Include roadmap-style pages explicitly in the post-impl sweep and look for stale "we could add X" prose where X is the capability just shipped. *Learned:* hiveplotlib #46 Workstream I tore out `from_networkx*` and consolidated onto `HivePlot(graph=...)`; `docs/source/roadmap.rst:50` retained the "we could add `HivePlot.from_networkx`" bullet because the capability shipped via a constructor parameter rather than the proposed static method.

- **Walk the first-error experience for the muscle-memory transition path.** When a public API changes shape (classmethod → keyword-only constructor parameter), users typing the prior shape will hit *some* error; the error they hit determines whether the transition feels supported or hostile. Locked recovery-oriented `ValueError` messages cover cases the validator catches, but the case where the prior-shape call binds positionally to a *different* parameter and fails downstream slips through. A defensive `isinstance(nodes, nx.Graph)` guard with a recovery message closes the gap (at the cost of an optional-import dance); default to low-confidence for unshipped pre-release surfaces and flag with the actual traceback so the user can adjudicate. *Learned:* hiveplotlib #46 Workstream I post-impl — `HivePlot(g, ...)` (old v0.27 shape) binds `g` positionally to `nodes` and surfaces as a confusing `AttributeError` in `add_nodes`.

- **For an ecosystem-specific duck-type guard, audit false-positives by walking the actual sibling libraries' method names, not by eyeballing "the predicate looks specific enough."** When a guard sidesteps an `import` to keep an optional dep truly optional, the predicate's discriminative power depends on which methods it picks: single-method probes typically collide across libraries; two-method probes often pin to one ecosystem because the second method's *name* diverges even when the capability is the same. Walk each candidate library's actual method names and write the per-library outcome into the post-impl review even when the predicate passes — that's what makes robustness legible to future reviewers extending the guard. *Learned:* hiveplotlib #46 muscle-memory guard post-impl — `hasattr(nodes, "is_directed") and hasattr(nodes, "is_multigraph")` is robust because the second method's name diverges across igraph (`has_multiple`/`is_simple`), graph-tool (no `is_multigraph`), and rustworkx (`multigraph` *attribute*); single-method probe on `is_directed` alone would have collided with igraph.

## Anti-patterns

- **Don't review a plan that cites an originating incident without verifying the incident's current state in the working tree.** Plans are drafted against a snapshot; the working tree can move between drafting and review (an unrelated commit corrects part of the issue, leaving a residue). When the plan cites a `file:line` as the originating incident, read that line as part of the review; if state has shifted, recommend updating the example (with a footnote naming the pre-correction state as motivation) or amending the plan's done-when to handle the asymmetric state. *Learned:* `rationalization-as-smell` planning-mode — plan's Example 2 cited `tests/hiveplot_matrix_test.py:2867-2893` for a both-audits-fire scenario; the test body had already been corrected, leaving the rationalization paragraph at 2874-2876 but no test-name-contract mismatch.

- **Don't treat "mechanical propagation" as exempt from review.** When a sibling class gains a surface that mirrors another class's API (`HivePlotMatrix` mirroring `HivePlot`'s graph-features API), the new surface is still a fresh first encounter for users of the sibling class. Walk it from scratch as if the parent surface didn't exist. *Learned:* hiveplotlib #46 Workstream F framed as "API propagation, not redesign" made the dispatcher skip post-impl api-critic entirely; codified in mental-model rule 7, qa-engineer step 12, and the plan template.

- **Apply the first-encounter-discoverability lens to reader-facing harness surfaces (CHANGELOG entries, rule prose, agent-report shapes), not just Python APIs.** A CHANGELOG reader, an agent reading an amended rule on first invocation, and a dispatching session parsing a report all share the single-shot encounter property. Probe: ask "what does the reader land on in the first sentence, and is the load-bearing behavior there or three sentences in?" For process-rule workstreams (carve-outs, new constraint bullets, contrastive phrasing), the strongest test is walking three concrete future-agent scenarios end-to-end — canonical case + debugging-edge case + gameable-rationalization case. *Learned:* `harness-changelog-and-line-endings` planning-mode (front-loaded structural detail across CHANGELOG / rule prose / report shapes) and `make-targets-exclusively` post-impl (three-scenario walk surfaced pytest-modifier coverage gaps the prose didn't catch).

- **For harness-self plans whose "API" is an agent's report format, audit the report vocabulary as if it were a Python signature: every new token forces dispatching sessions to learn a second axis.** When the plan proposes a new state on an existing report line, check whether an existing channel already carries the same information. The qa-engineer's `Status: pass | fail | propose` already encodes "everything green but reviewer concerns surfaced" via `propose`; a new sibling state on a sub-line that demotes `Status` to `propose` for the same fact creates two parallel ways to communicate one thing. Redefine the existing token (`pass` = zero warnings) and route through the existing channel. *Learned:* `qa-engineer-docs-warning-posture` planning-mode — proposed `Docs build: pass-with-warnings`; rejected `propose` for "token overlap" when the overlap was the *reuse signal*, not the friction.

- **When extending a numbered taxonomy, the new entry's grammatical shape must match the existing entries' shape, not just their content domain.** Existing entries develop micro-conventions (length, imperative voice, cross-reference style, parenthetical presence/absence) that a reader registers as the local grammar; a new entry that breaks it reads as more important than siblings on grammatical weight alone. Render the taxonomy as a flat list and read aloud — the new entry should be indistinguishable in cadence; trim parenthetical / follow-on sentences the others don't carry. *Learned:* `rationalization-as-smell` Workstream A — new rule 16(a) bullet carried a parenthetical and follow-on absent from sibling bullets; new (c) entries used noun-phrase headers ("**No silent substitution.**") while existing (c) used imperative phrases under "do NOT:", mixing grammars into a soft double-negative.

- **When a catastrophic-severity case has no slot in the routine state machine, prefer an out-of-band escape-hatch report shape over adding a fourth value to every agent's `Status:` line.** Adding a fourth value fails *unevenly*: work-agents have `complete | partial | blocked`; qa-engineer has `pass | fail | propose`; critics have `clean | propose` — four-of-nine agents have no slot. An escape-hatch template (uppercase `STATUS: BLOCKED` first-line standalone, *replacing* the routine report) works uniformly; case and position differences signal "out-of-band severity, not routine state." *Learned:* `halt-on-confusion-and-ban-destructive-ops` planning-mode — plan framed `STATUS: BLOCKED` as reusing the `blocked` state from work-agents' line; qa-engineer and critics lack it.

- **When a harness rule fans out to N agent definitions, harden cross-file consistency from "consistent" to "verbatim-equal" on the load-bearing tokens.** "Consistent" admits paraphrase; "verbatim-equal" doesn't. The risk concentrates on tokens the dispatching session and downstream agents pattern-match against (report headers, verb pairs, rule citations); paraphrase forces dispatchers to learn N variants of one canonical token. Identify the tokens in planning mode and recommend the Quality bullet name them with verbatim-equality. *Learned:* `halt-on-confusion-and-ban-destructive-ops` planning-mode — rule 9 + rule 16 fan out to 9 agent defs + 2 CLAUDE.mds + template + mental-model; load-bearing tokens are `STATUS: BLOCKED` and `STOP and surface`.

- **For harness-self plans, distinguish "owning-specialist axis" from "scope axis" in carve-out rules.** Exemptions can be keyed on (a) which specialist owns the workstream or (b) what the scope is; the two diverge on code-engineer-led docs work (specialist != docs-engineer, scope IS docs) and docs-engineer-led API renames (specialist == docs-engineer, scope is API). User directives almost always pin scope; orchestrator plans often shorthand to specialist because greppting the dispatched specialist is mechanically simpler than parsing scope. Pivot carve-out terms to scope nouns (`docs-scope workstream`, not `docs-pass workstream`) and define operationally against the workstream brief. *Learned:* `qa-engineer-docs-warning-posture` review — plan's carve-out keyed on "dispatched specialist is docs-engineer"; user directive named "follow-up tasks are explicitly docs additions / fixes" (scope).

## Gotchas

- **Planning-mode proposals built on unverified identity / aliasing claims need empirical verification before they ship.** When a finding proposes an `id()`-based key change, it rests on an implicit empirical claim about which inner objects are aliased across which construction paths. Implementing without checking can ship a widening that fires for narrower cases than the brief implied; if post-impl reveals the dedup doesn't trigger for the natural-constructor case, read the construction chain and identify the *one* attribute level whose identity actually survives. *Learned:* hiveplotlib #46 Workstream G — `(id(hp.nodes), id(hp.edges._data))` shipped based on a Workstream F finding; empirically `Edges._validate_edge_data` rebuilds the outer dict so the outer id isn't aliased across `HivePlot(nodes, edges)`. Inner DataFrames within `_data` ARE aliased; right key is `(id(hp.nodes), frozenset(id(df) for df in hp.edges._data.values()))`, recommended as Workstream H.

- **When adjudicating "accept narrow vs. widen further" for a perf-only fix, weight notebook English as the tiebreaker.** The bounded-worst-case argument (Nx slowdown; values identical) makes the fix sound deferrable. But if user-facing prose already promises the wider behavior (markdown describing "computed once on shared data" when code computes per-cell), the prose-vs-code mismatch is a correctness concern in the api-critic's lane; pick recommend-follow-up over accept-as-is. *Learned:* hiveplotlib #46 Workstream G — `examples/hpm_generic.ipynb` promised "computed once on shared data" which the narrower dedup didn't deliver.

- **After a tuple-shaped identity key is widened to a set-shaped one, run the "what does collapsing repeated ids change?" check before signing off.** Tuple `(id(a), id(b))` carries multiplicity and order; `frozenset({id(a), id(b)})` loses both. Order loss is usually wanted; multiplicity loss is the one to inspect. Walk natural construction paths; if none produce same-object-under-multiple-keys aliasing, log the pathological case as low-confidence with a `tuple(sorted((tag, id(df)) for ...))` fix sketch. *Learned:* hiveplotlib #46 Workstream H widened to `frozenset(id(df) for df in hp.edges._data.values())`; pathological `Edges(data={"tag_a": df, "tag_b": df})` collapses to one element; verified no natural construction produces this aliasing.

- **A vocabulary refactor that swaps a one-token noun for a multi-token noun-phrase breaks parallel-clause symmetry; flag the rare parallel-construction sites at planning time, not post-impl.** Replacing `(nodes, edges)` with "the `nodes` and `edges` parameters" reads cleanly on error messages, ledes, and `:raises:` lines. Friction concentrates on sites where the original was *paired with another one-token noun in a parallel clause*: "the `(nodes, edges)` initialization defaults to ... ; the `graph` initialization defaults to ..." becomes asymmetric because the "and" inside the first half competes with the parallel separator. Recommend at planning time that surrounding sentence shape change too — possessive-noun ("the X initialization") to participial-clause ("when initialized with X") — so the parallel form survives. *Learned:* hiveplotlib #46 Workstream L planning-mode — property docstrings at `hiveplot.py:2163,2169,2171` and `hiveplot_matrix.py:617-624` used parallel constructions that the mechanical substitution weakened.

- **When a vocabulary-refactor workstream defers a user-facing sub-surface ("X is docs-engineer's later call"), the post-impl review is the deferral-collection moment, not a free pass to leave it deferred.** A scope of "source + tests + notebooks" that defers CHANGELOG, migration guide, or blog notebook tends to result in stale vocabulary shipping because no follow-up dispatch gets created. When qa-engineer pre-flags as `worth-discussing`, default to **uphold-and-escalate** (must-fix) when (a) the deferred artifact ships with the release, (b) the literal phrase load-bears on the user's mental model, and (c) the fix is a small mechanical word-swap with no rendering risk. *Learned:* hiveplotlib #46 Workstream L post-impl — code-engineer log deferred CHANGELOG to "docs-engineer's later call"; qa caught two CHANGELOG hits using L-locked vocabulary; api-critic escalated for v0.28.0.

- **Done-when criteria are the post-impl contract; an unmet Done-when item upgrades qa's `worth-discussing` to `must-fix`.** Workstreams whose dispatch brief enumerates a subset of touched files drop the un-enumerated edit silently; qa-engineer often catches the omission but tags `worth-discussing` because it reads Files and Implementation log without cross-referencing Done-when line-by-line. The post-impl critic IS the agent that reads Done-when as the binding contract; before signing off, walk each Done-when bullet against the Implementation log and the shipped diff. *Learned:* `data-shape-audit-and-feasibility-checks` Workstream A — Done-when required api-critic.md workflow step 3 to "explicitly check for realistic data construction"; dispatch brief framed as "four locked drafts" missed it; qa flagged `worth-discussing` (existing bullet resolved in spirit); api-critic upgraded.

- **For post-impl review on a workstream specifically motivated by closing a semantic-coherence gap from a prior workstream, the resolution-verdict is the load-bearing output; treat it as mandatory and frontload it above the routine surface-walk.** Read the prior workstream's failure-mode description, then walk the diff asking "is this exact failure mode now closed?" and "does the new surface promise more than the closure, and if so does it deliver?" Forced binary (yes / yes-with-caveats / no) plus a one-paragraph rationale, frontloaded; routine friction list still lands beneath. *Learned:* hiveplotlib #46 Workstream N post-impl — closed the `from_tags(graph=...)` single-tag-collapse flaw from Workstream F (preserved through I); surface-walk surfaced one low-confidence (edgeless graph silently produces `(1, 0)` matrix); verdict was the strong signal.

- **reST emphasis spans do not parse inline-literal markup, so prose-polish fixes that nest `` ``token`` `` inside `*...*` will render backticks literally.** Workable shape: plain text inside emphasis (`when graph= is provided`) with trailing `=` doing the kwarg-signaling work; the surrounding parenthetical clarifies kwarg vs. ordinary prose. When the prefix is a cluster-level header rather than a per-param qualifier, append the literal word "sub-family" to disambiguate. *Learned:* hiveplotlib #46 Workstream J extension — Sphinx collapses blank-line breaks between consecutive `:param:` entries; code-engineer fell through to the prefix-style fallback, adding "sub-family" and dropping inline-literal styling on `graph=`.
