# Expertise: Adversary

Curated playbook of what this role has learned. **Not a log.** Edit existing entries when a new observation refines or supersedes them; add new entries only when truly new ground is covered; remove entries that no longer earn their place. Every entry comes from a real failure or repeated success (not invented advice), follows the entry shape (lead + body, no originating-plan citation), and stays lean (soft target ~60-90 words) per mental-model rule 11.

Read the cross-cutting `agent-harness/.claude/expertise/personal-gotchas.md` at task start in addition to this file.

## Patterns to reach for

- **A skip reason written as prose is not enforcement; demand a mechanical arming trigger for any dormant or skip-marked gate.** When a plan marks a gate skipped or dormant ("run this once X lands", "n/a until the rubric exists"), the recorded reason re-arms nothing: no one re-checks it when the condition flips, and the gate stays off indefinitely. Push for a named trigger someone will actually hit (a done-when bullet, a dispatch-time check, a grep target) that fires when the condition arrives. Trigger: any "skipped for now" without a stated un-skip mechanism.
- **On harness-self plans, diff the routing vocabulary across every surface the plan touches before trusting its wiring.** Tag and trigger vocabularies drift between surfaces (one rule said findings route on `must-fix` or `should-fix`, a tag no critic emits, while the adversary's own spec routes `worth-discussing`); a new mode built on "halts on any amend-plan trigger" inherits whichever reading the implementer happens to hold. Two blind spots: a workstream shipping *before* the reconciling one can mint fresh taxonomy statements its surface list never named, and a sweep anchored on the retired token cannot find statements that never contained it. Trigger: any plan whose behavior keys off tags, triggers, or sequence phrases stated in more than one file.

- **When a plan's enforcement grep has multiple alternation clauses, run every clause against the deliberate survivors, not just the headline one.** A migration plan's own CHANGELOG notice necessarily contains the swept vocabulary; its holdout bookkeeping recorded the match for the clause the amendment was debating (`hiveplotlib[dev]`) while a second clause of the same gate (`optional-dependencies`) matched the adjacent line and a kept config table, leaving the plan-end sweep to false-fail or ad-hoc waive. Check each clause independently and demand every legitimate match be recorded. Trigger: any "anything outside Holdouts fails" gate whose pattern contains an `|` or a second search term.
- **When a plan grows sibling branches of the same capability, diff their done-when gates against each other; the weakest sibling is the contract an implementer builds to.** A Dask input branch required output equivalence to the pandas path while the polars branch on the same dispatch boundary required only "works end-to-end" plus frame-type round-trip — leaving an engine-specific wrong-selection bug free to render a confident wrong picture with every stated gate green. The richer sibling's gate is usually the honest standard; a missing mirror bullet is a finding, not a style nit.
- **When a diff extracts a shared helper and ships "bit-identical" equivalence tests, check the comparison topology before crediting the claim.** Twin-instance tests where both sides route through the extracted code prove delegation and parameter passthrough, not fidelity to pre-refactor behavior: a divergence introduced by the extraction moves both sides together and every gate stays green. Ask what in-tree artifact pins pre-refactor output (a golden fixture, pinned values); if none exists, the claim rests on code reading alone and deserves at most a low-confidence credit plus an optional pinned-value smoke. Trigger: any refactor whose equivalence baseline shares the refactored code.
- **When a multi-engine abstraction ships verified against one engine, grep for duck-typed attribute reads on user objects; they are the sites the conversion sweep skipped.** A boundary refactor's site sweep finds explicit idioms (`.loc`, `set_index`, `np.where(df.columns == ...)`) but skips reads like `x in df.columns` that happen to work on the tested engine, leaving them un-routed while the docs claim "any supported engine" — on an engine where the attribute means something else (pyarrow's `.columns` is arrays, not names) the feature silently misresolves with every gate green, since the gates only run the tested engine. Same pass: check fast-path-exempted sites that wrap guaranteed-internal objects anyway; they reject the degenerate inputs (duplicate/non-string columns) the fast-path exists to preserve. Trigger: any "supports any X-compatible library" claim whose test matrix names fewer engines than the docs do.
- **A plan that instructs an edit to another active plan goes stale twice as fast; verify the target text still exists at challenge time.** Sibling plans self-correct through their own adversary/grill loops: an instruction to fix a false claim in a second plan aimed at text that plan had already amended away weeks earlier (its own challenge disposed the same issue, and the workstream carrying the claim shipped), leaving the edit unexecutable as written. An implementer hitting the missing target either halts or improvises edits into a foreign active plan. Trigger: any Files bullet or design note whose edit target is another plan file.
- **When a workflow conditions a capability on existence ("when X exists"), check the output grammar and the pass gate for the absent branch.** A conditional workflow step paired with an unconditional report field or gate makes the honest report unrepresentable: a dependency-audit run gated "when tooling exists" shipped with only `clean | unresolved` in the field grammar and "tool run clean" required for pass, so a consumer without the tooling could neither report truthfully nor pass. Trigger: any `<a | b>` report grammar next to a "when/if it exists" workflow clause.
- **When a plan's call-site inventory is pinned to a ref the working tree isn't on, reconcile by counts and groupings instead of declaring it unverifiable.** Grep the working tree for the swept pattern, bucket by file, and diff against the inventory's per-file counts: matching counts with small line offsets corroborate the inventory, while surplus sites are exactly the sibling-branch additions the plan's coordination notes tend to under-describe (one "helper on the datashader route" turned out to be two bare warn sites in a different file the plan itself edits — a merge surface and a future invariant break in one). Trigger: any "citations against <ref>" plan reviewed from a divergent checkout.
- **When a done-when demands "runnable verbatim from a fresh shell," walk the toolchain above the documented block, not just the commands inside it.** A dev-setup migration's commands all checked out line-for-line, but the happy path's first step (`make install`) invoked a tool (`uv`) the docs never say how to obtain — the fresh-machine wall sat one layer above every audited command, invisible to a block-by-block verbatim check. Start the walk at the reader's actual first keystroke and treat each binary invoked as a claim needing an install pointer. Trigger: any contributor-docs done-when phrased as "runnable verbatim" or "fresh machine".
- **When a diff strengthens a rule to a universal quantifier, walk every untouched section still governed by it; the collision hides exactly where the diff didn't reach.** A grill-me rewrite upgraded "pre-fill where the plan settles a question" to "recommended answer first, every question, whether or not the plan leans one way" — and the untouched failure-mode wave three sections later depends on the opposite mechanic (the maintainer names the modes; a model-authored list is the named failure). The old scoped phrasing never reached elicitation; the new "every" did, un-anchoring the rubric downstream passes attack against. Grill approval of the headline wording is not approval of the interaction. Trigger: any edit adding "every/always/all" to a rule whose mode has sibling steps the diff leaves untouched.
- **When a plan adds a key to a shipped stored structure, audit its lifecycle by grepping every writer and reader of its sibling keys, not the one method that creates it.** A per-subset geometry record written at one creation site was claimed safe because the serializers "iterate fixed key lists" — but those loops deep-copy the whole record and iterate only to *convert* two values, so every other key rides into the public JSON (the neighboring key already proves it). The same audit found a second public method that rebuilds the state the record describes without touching the record, so a later read renders geometry the user changed away from. Trigger: any plan adding a key alongside existing keys in a dict a shipped class owns.
- **When an amendment supersedes a design and keeps the old spec's done-when list "except as changed", grep the survivors for the deleted noun.** A collapse that dropped a stored geometry record replaced two bullets and dropped one, leaving a fourth that still required "unpersisted chunks build at their recorded geometry" and asserted the untouched arm was "behavior as today's" — the exact arm the workstream existed to change. Delta-amendments inherit the retired vocabulary silently, and the survivor bullet contradicts the replacement bullet a few lines above it. Trigger: any amendment whose done-when is stated as a delta over a superseded list.
- **Check every warning or error message the plan specifies against each arm of its own trigger; the multi-arm message usually serves one arm.** A drop-site warning fired on four parameters and named two remedies that only addressed one of them, with the working lever for the other three (a kwargs dict on the same entry points) unnamed. The same plan had already had a warning rejected for pointing at a method the warned user could not call, and the replacement reintroduced the shape one arm over. Enumerate the trigger's arms, then read the message once per arm. Trigger: any spec'd message whose trigger is a disjunction.
- **When a plan adds a conditional that skips an existing call, ask what happens to the arguments that call was carrying.** A new "skip when the flag is off" gate over `connect_axes`'s eager construction call said nothing about the four geometry parameters that call passes, so an explicit request would vanish silently: verbatim the drop-it-on-the-floor defect the sibling lazy arm had just shipped a warning to close, reintroduced one arm over by the gate. Cheap to land, since the fix is usually widening the existing warning's trigger rather than new machinery; check the widened trigger for spurious fire against in-tree callers. Trigger: any "skipped when X" design over a call site that takes parameters.
- **When a plan settles a commit boundary inside one workstream, check each commit for reads of state that lands in a later commit.** A slice put two bug-fix commits ahead of the feature commit and claimed "the order is buildable as written"; the first commit's new guard carried a conditional clause reading an attribute the third commit introduces, so the clause was not "never true" but an `AttributeError` on the exact path that commit's own tests exercise, plus a type-check failure. Writing it defensively instead buys a permanently-dead branch, which a 100% gate rejects. Walk each commit against build, its own tests, and coverage. Trigger: any amendment settling commit order for review legibility.
- **When a plan defends a silent-ignore by citing house precedent, check the other half of the house's habit and classify the ignored parameter as hint versus state request.** A "documented as ignored, does not raise" rule cited a perf-hint parameter ignored for incompatible reductions; the repo also raises a legible `ValueError` on a well-typed, individually-meaningful parameter combination, which is the nearer shape. The dividing line is not typo-versus-meaningful but observable-versus-invisible: ignoring a hint changes nothing the caller can see, while ignoring a state request costs them the thing they called for. Also ask whether honoring it in both directions deletes the special case. Trigger: any "ignored, not raised" rule justified by one cited precedent.
- **On a second post-impl pass over one workstream, re-read the amendment stack before trusting what your own earlier pass deferred; a "still owed, not chargeable to this diff" bullet goes stale when a later amendment promotes that item into a done-when.** A first pass read the live revision as parking a memory measurement downstream and recorded it as owed by a later workstream; an in-scope tweak landed the same day moved it to this workstream's close with a pre-registered band and the words "not done until the verdict is in the log," and a still later amendment re-affirmed it. Plan-section-as-memory is a record of what you said, not of what the plan now requires. Trigger: any post-impl re-run where a prior pass on the same workstream exists.
- **When a plan claims a test harness catches errors "by construction", name the failure shape it actually detects and hand it a wrong-but-running input.** An execution-based docs-snippet harness catches run-failures only; a `**kwargs` API absorbs a misplaced keyword silently, so a snippet teaching a wrong idiom stays green (seen: `method(all_edge_kwargs={...})` merging a dict-valued kwarg named `all_edge_kwargs` instead of setting the kwargs, no error until an unrelated later render). Verify representative snippets against live signatures; "runs" is not "correct". Trigger: any "the test catches this by construction" sentence.

- **When a grill generalizes one incident into a rule, replay the incident against the rule's own arithmetic before crediting the mitigation.** A wave replaced a tolerance band with a sampling protocol after a headline figure proved non-reproducible; the offending number's own two samples spread 6.5% against a 10% band, so the new rule republishes it, and only a separate ad-hoc ruling keeps it out. Same pass, same root: rules written for one number per child break when the protocol yields N numbers, several kinds per child, and ratios across children, none of which the bands, the verdicts, or the deferred-summary-statistic clause can express. Trigger: any mitigation stated as a rule generalized from a named failure.

- **When a plan retires or absorbs a control, enumerate the jobs it was doing from the source text and check each landed; the retiring rationale reliably names one.** Two shapes. An amendment dissolving a grill-added disposition state argued only its publication half ("protected a convention now discarded") while its second job, blocking a binary verdict the grill had called wrong, silently reverted. A plan declaring it *supersedes* a sibling plan's headline change quoted only that change's "a section inside a 431KB document still needs opening it" rationale and never engaged its stated per-workstream firing cadence, which was the half tied to the incident both plans exist for. Read the superseded text yourself; the absorbing plan's self-description is not evidence of coverage. Trigger: any "dissolved rather than repaired" disposition, or any `## Disposition of the sibling plan` claiming absorption.

- **On a harness-self plan, check which copy the verification touches: the harness source is inert until `make sync`, and the live artifact is the consumer's `.claude/` copy.** A probe workstream designed to test whether a `tools:` grant works listed only `agent-harness/.claude/agents/<x>.md` in its Files, but Claude Code reads `<consumer>/.claude/agents/<x>.md`, which `sync.sh` overwrites from source. Editing source alone makes the probe return a null result, and the workstream defined a null as "refuted, plan dead". Second shape, same root: a dispatch brief asserting an already-applied harness edit *worked* ("the widened skill description fixed the firing, the redraw came out better"), when the consumer's synced copy still held the old text, so nothing had tested the fix; grep the consumer's `.claude/` copy before crediting or discrediting any such claim. For skills specifically, do not reach for "the list is fixed at session start" as the reason: that was observed false on 2026-08-22, when `sync.sh` run mid-session re-emitted the listing with the changed description. The observing session is still not the test, for a different and harder reason: it already knows what the change was meant to do, so its behavior is contaminated rather than blocked. Contamination is the thing a fresh session buys. Trigger: a harness-self done-when, or a briefed premise, whose evidence is runtime behavior rather than a file's contents.

- **No Bash means no git diff; reconstruct the artifact instead of halting, and say in the report that the diff was not read.** Two baselines work. On a consumer post-impl pass over a shipped commit with a clean tree, the working tree at that tip *is* the artifact: read the sites the spec names and grep the feature's whole surface (`rg <flag>` across `src/` and `tests/`) so a change outside those sites is a stated blind spot rather than an unstated one. On harness-self passes, the consumer's stale `.claude/` sync copy is a legitimate pre-change baseline, since Holdouts names synced copies "expected-stale until `make sync`". Either way corroborate with absence-greps for swept phrasing. Trigger: a post-impl dispatch naming a `git diff` command in a context without a Bash tool.

## Anti-patterns

- **When you file "no equals-in-memory anchor" as a coverage must-fix, do NOT then reason the untested path is correct anyway; the missing anchor IS the tell the two paths were never proven equal.** On a lazy/eager dual path I flagged the absent completeness test as a must-fix, then in the same block cleared "composition correctness holds" by asserting the broad seed made membership "trivially true for every in-tag edge" — a claim I read off the code instead of tracing by construction. It was false (in-memory resolves the expression to endpoint NODES then closes; the lazy literal filter kept only literally-matching edges: 54 vs 40 edges). The coverage gap was hiding a live divergence, not an untested-but-correct path. When one branch is unpinned, treat "it still matches" as unproven, not as a thing to argue sound; downgrade any equals-the-other-path verdict to low-confidence until an in-tree equality anchor exists. Trigger: your own report filing a missing cross-path equality test.

## Gotchas

- **In any same-process A-vs-B measurement, check what the instrument carries over from phase A before trusting phase B's number.** Two shapes seen: timing ratios, where whichever side runs first absorbs one-time import/JIT/cache-warming cost (a warm-up call or order swap is the cheap control); and monotone peak counters (`ru_maxrss`, RMM `peak_bytes`, allocator high-water marks), where the second phase's "peak" is by construction ≥ the first's and inherits its retained allocations — a suspiciously clean 2x between two routes measured back-to-back in one process is the tell. Demand per-phase isolation (fresh process, or a reset/push-pop counter scope) before accepting either number as evidence.
