# Expertise: Test Engineer

Curated playbook of what this role has learned. **Not a log.** Edit existing entries when a new observation refines or supersedes them; add new entries only when truly new ground is covered; remove entries that no longer earn their place. Every entry comes from a real failure or repeated success (not invented advice), follows the entry shape (lead + body, no originating-plan citation), and stays lean (soft target ~60-90 words) per mental-model rule 11.

## Patterns to reach for

- **Empirically verify dedup / identity preconditions before writing the assertion.** When a brief asserts "these two objects share `id(X)`," REPL-check it first; briefs assume aliasing that may not hold (e.g. `Edges.__init__` -> `_validate_edge_data` builds a fresh dict, so two `HivePlot(nodes, edges)` calls do **not** share `id(hp.edges._data)`). If false, surface the gap and test an artificial scenario that *does* hit the path (e.g. `hp_b.edges = hp_a.edges`). Trigger: dedup tests, identity-based caching tests, "metric computed once" tests.
- **Monkey-patch lazy-imported function-local references via the module attribute.** When source does `def foo(): from mod import func; func(...)`, patch `mod.func` (or `monkeypatch.setattr(mod, "func", wrapper)`), not the importing module: `from X import Y` re-resolves each call. Pattern: dedup-counter and side-effect-counter tests for lazily-imported helpers.
- **On test-deletion / parametrize-pruning briefs, run the full failing suite first, then cross-check the brief's enumeration.** Briefs name the obvious removals but miss siblings that pass the now-removed kwarg via an intermediate helper (e.g. `_call_consolidated("from_tags", graph=g)`). The post-revert `pytest tests/<file>.py -n 7 --no-cov` output is ground truth: every failure not in the brief is a sibling the brief missed; cite each in the Implementation log as targeting the removed surface, don't self-recover or skip. Trigger: any "remove tests for the just-reverted surface" brief, especially parametrize-decorator surgical drops.

- **Prove a new test is falsifiable by mutating a `/tmp` copy of the source, never the working tree.** When the maintainer is mid-review (files staged, concurrent edits), the usual "break the source, watch it go red" loop is banned. `cp -r src/<pkg> /tmp/<scratch>/`, patch the copy, then point the *real* suite at it: `PYTHONPATH=/tmp/<scratch> .venv/bin/python -m pytest <file> -k <sel> --no-cov -rf` beats an editable install (confirm `<pkg>.__file__` resolves to the copy), so you see the exact failure a regression would print. Prefer a partial mutant (drop half the built rows) to a total one (return empty), which tends to die inside the plotting library before reaching your assertion. One mutant per claim, including the difference assertions.

- **To append a class at a file's true end, anchor on the file's actual last lines, not a recurring body line.** When a new test class goes "after the last networkx class," the `old_string` must be the file's genuine tail (confirm via `wc -l` + a Read of the final lines, or `git show HEAD:<file> | tail`). Matching a generic body line (e.g. `assert "triangles" in hp.nodes.data.columns`) that recurs across near-duplicate methods inserts the class mid-file, splitting the surrounding class and orphaning trailing methods/asserts (silent until the parent class's tests fail with `AttributeError`/`assert None is True`). Trigger: appending a class/method block to a large test file.

- **Derive parametrize lists and fixture selection from the declared source of truth, not parallel hardcoded lists.** "Parametrize aggressively" over a typed-out list of names breeds copies that silently drift (three hand-kept lists of "directed metrics" had already diverged). When a test enumerates "all X with property P" or picks a fixture by category, read P off the registry / decorator metadata (e.g. `_hpl_graph_type_requirement.requires_directed`) so new entries auto-track. But derive only *inputs*; never derive the assertion from the artifact under test, or the test goes tautological. A genuinely inexpressible case (DAG-ness, which `GraphTypeRequirement` can't encode) earns one explicit branch. Trigger: a parametrize decorator or fixture switch fed by a literal list of metric/feature names.

## Anti-patterns

- **No bug archaeology or review history in test docstrings.** Mechanism prose rots on refactor and history lives in git blame; state the behavior under test, full stop. Process/role provenance counts too: citing a plan item, critic, or review mode as the reason a test exists leaks plan metadata into a shipped artifact (rule 15). Trigger: "Regression test for X" framing, "failing-before" prose, or a critic/review-mode/plan-item citation.
- **Keep a marker or test-layout invariant note to a sentence or two.** When a selection rule earns a written record (a `pytest.ini` marker description, a backend module's docstring), that prose competes with the tests for the reader's attention. Both landed long on 2026-08-02 and both came back the same day: the `pytest.ini` note was "long winded, considering how we've been doing things," and the module-docstring additions "correct but unnecessarily wordy." State the invariant and what breaks when it is violated; leave out the derivation, the collection counts, and the CI-selector history.
- **Rendering-only surfaces aren't test targets (mental-model Test discipline).** `__doc__`/`__name__`/`__qualname__` with no library consumer are covered at import and owned by docs review; a unit test on them is orthogonal in a behavior suite.

## Gotchas

- **A test named after an entry point must call that entry point literally, even where the file has a render/act helper.** `datashader_test.py` wraps every render in `_edge_raster(...)`, so a new `test_datashade_edges_mpl_*` case using it satisfies the spirit and still trips `audit.sh test-contract` as `[no-ref]` (the audit greps the body for `<name>(`). A dozen pre-existing hits in that file and `dask_test.py` make the noise easy to inherit. Fix cheaply: open the test with `from <mod> import <entry_point>` and define a local closure calling it, which keeps the helper's shape and the literal call. Run `audit.sh <consumer-path> test-contract` (consumer path FIRST; an audit name in slot one is silently ignored and the current directory is scanned) before and after, and diff.
- **`audit.sh test-contract` is nondeterministic on tie-length candidates; diff the test-name set and re-run before blaming your change.** It picks `max(candidates, key=len)` over a `set` of source function names, so equal-length candidates (`backend` vs `wrapper`, `tags` vs `copy`) resolve by hash order and hits appear and vanish between runs on an untouched tree (2026-08-20: 76, 76, 76, 78 across four runs). Compare sorted `grep -o "test '[a-z_0-9]*'"` output before/after rather than raw `diff` (which also churns on line-number shifts), and re-run any apparently new hit before treating it as yours.
- **Type-checking a container whose accessor returns `T | None`: bind to a local and assert, don't chain.** `hpm[0, 0].set_persist_curves(...)` is a `ty` error (`Attribute ... is not defined on None in union HivePlot | None`) even where the test just built the cell, and `make ty` gates CI. `cell = hpm[0, 0]; assert cell is not None; cell.set_persist_curves(...)` type-checks, keeps the accessor in the test, and makes the precondition explicit. Trigger: any test reaching through `HivePlotMatrix.__getitem__`.
- **Import-path tests: re-import the class under its own name, no alias, no defensive noqa.** When a test body pins a public import path (`from pkg import ExportedClass`) that the module also imports top-level, a lowercase alias (`as top_level_import`) trips N813, and a pre-emptive `# noqa: PLC0415` trips RUF100 when PLC isn't in the ruff selection. A same-name function-scope re-import passes every selected rule and still proves the path; check `extend-select` before reaching for noqa. Trigger: importability tests for re-exported classes.
- **Ruff's D205 + E501 collision on docstring summary lines.** Folding a multi-line summary onto one line for D205 ("blank line between summary and description") often pushes it over 120 chars and trips E501. Fix both at once: pick a summary short enough to fit on one line *and* read as a single sentence. Trigger: adding a `:py:meth:` cross-ref to a summary line.
- **A top-level optional-backend import in a test module breaks collection in the minimal `performance_gates` env, and the marker does not save you.** That job installs only `.[perf,testing]` and selects with `-m`, but deselection happens after collection, so a module-top `from bokeh.plotting import figure` hard-fails the whole session where the backend is absent. A dev worktree with every backend installed masks it completely. House pattern: keep module-top imports backend-free, resolve the backend inside each test body (`import hiveplotlib.viz.bokeh`), and keep `pytestmark = pytest.mark.<backend>` for the skip.
- **A module-level `pytestmark` is additive: a per-test optional-dep marker joins it rather than replacing it.** `pytestmark = pytest.mark.unmarked` plus `@pytest.mark.polars` on one method makes that test match `-m unmarked`, so a base (no-extras) CI install collects and runs it and dies on the optional import. Verify with `pytest --collect-only -q -m "<blanket> and <optional>"`; a non-zero count is the bug. Fix per file: move standalone optional-dep tests into that backend's own module, and for tests parametrized over the dependency make every case's mark explicit (`pytest.param("pandas", marks=pytest.mark.unmarked)`) with no module-level blanket. When a test needs the marked dependency *plus* another backend, leave it in place and open the body with `pytest.importorskip("<other>")` (precedent: the `nx_parallel` tests in `graph_features_test.py`); confirm in the full env that it runs rather than skips, or the coverage goes quiet behind a green pipeline.
- **Before adding an extra to a per-extra CI add-on matrix, install *only* that extra in a scratch venv and run the job's actual selector.** A marker that names an input-boundary library (polars, dask) tends to also cover cross-backend equivalence tests that import datashader/bokeh/plotly/holoviews, and the extra itself may omit transitive test-time needs (`hiveplotlib[polars]` has no pyarrow, which every `pl.from_pandas` / `to_pandas` test requires). `-m "$ADDON or unmarked"` selects the whole marker set, so both gaps land as hard failures the full dev worktree cannot show you. Separately, `uv pip install 'pkg[unknown-extra]==<ver>'` only *warns* and exits 0, so a released-code job pointed at a tag predating the extra installs the base package silently rather than erroring.
- **A test that pins WHICH source a value resolves from is blind whenever the fixture sets that value to the library default.** Twin helpers for render-time curve geometry built instances at the default `num_steps`, so "the rebuild takes the construction default" and "the rebuild takes the instance attribute" both passed, and a wrong docstring shipped at two entry points before the adversary caught it (2026-08-14). Any resolution-chain test (explicit argument, then per-object record, then instance attribute, then library default) needs every fixture value distinct from the default and from each other, or the chain is untested wherever they collide. The fix shape that bites: run the *same* call on a second instance declaring the default and assert the two results differ, so the losing reading of the chain fails rather than coinciding.
- **`nodes_edges_to_networkx` round-trip tests need disjoint `(from, to)` pairs across tags on non-multigraph targets.** Parametrizing over `(directed, multigraph)`, the `multigraph=False` cases land on `nx.Graph` / `nx.DiGraph`, which silently merge duplicate edges (last write wins; see the converter's `note::`). Two tags sharing a `(from, to)` pair fail `recovered_pairs == original_pairs` on the `[graph]` and `[di]` parametrizations only. Fix: disjoint `(from, to)` pairs per tag in fixtures, or restrict the parametrization to multigraph cases.
