# Expertise: Code Engineer

Curated playbook of what this role has learned. **Not a log.** Edit existing entries when a new observation refines or supersedes them; add new entries only when truly new ground is covered; remove entries that no longer earn their place. Every entry comes from a real failure or repeated success (not invented advice), follows the entry shape (lead + body, no originating-plan citation), and stays lean (soft target ~60-90 words) per mental-model rule 11.

## Anti-patterns

- **No CHANGELOG entry for refinements to a feature debuting in the current unreleased version.** Rule 13 (and step 7 of this agent's brief) says "append CHANGELOG for user-visible work," which agents over-apply. When the feature itself is new in the top unreleased `Version X.Y.Z` block, a refinement to it (a new validator, a reworded guard message, an inference tweak, an internal refactor) is not a change to announce against any released behavior; it folds into that feature's single first-release entry. Real case (2026-05, graph-metrics on the v0.28.0 cycle): four such entries were added across sessions and the maintainer had all four removed. An entry is warranted only when behavior changes relative to a PRIOR released version; internal refactors with unchanged observable behavior belong in the plan's Implementation log, never the CHANGELOG.

## Gotchas

- **Widening required params to `Optional` for runtime-validated mutual exclusion needs `assert ... is not None` afterwards.** When a parameter is `Optional[T] = None` resolved to non-`None` via a validation block (raising `ValueError`) or a derivation step (e.g. extracting `nodes`/`edges` from `graph`), `ty` cannot narrow the type across that control flow, so downstream calls expecting `T` fail type-check. Fix: add `assert nodes is not None` / `assert edges is not None` after the block, matching the `assert sorting_variables is not None` pattern at `hiveplot_matrix.py:1288`.
- **A decorator reading `func.__name__` trips ty (`Callable` has no `__name__`) and breaks for factory-built wrappers.** ty cannot prove an arbitrary `Callable[..., Any]` is a function, so `func.__name__` inside the wrapper fails type-check; and for wrappers built by a factory, `__name__` is the generic inner name at decoration time. Fix both at once: capture `name = getattr(func, "__name__", repr(func))` once in the decorator body (before defining the inner wrapper), and for factory products set `base.__name__` *before* applying the decorator so `functools.wraps` carries the real name through.
- **A set/list comprehension that filters `None` out of `Optional[T]` values still infers element type `Optional[T]` under ty, so `pop()`/return widens past `T`.** ty does not propagate the `if x is not None` guard into the comprehension's element type. Fix: bind the value with a walrus in the guard and yield the bound name (`{v for n in names if (v := f(n)) is not None}`), and annotate the target (`concrete: set[bool] = {...}`); ty then narrows the element to the non-`None` type.
- **Pass `dtype=object` to `np.array(...)` when the source list mixes element types.** numpy silently promotes mixed-type lists to `<U21` (unicode), turning int `0`/`1` into strings `"0"`/`"1"` with no warning; downstream code holding the original ints (dict-key lookups, `isinstance` checks) then breaks with `KeyError`/`TypeError`. Generalizes to any `np.array([...])` from a comprehension or mixed list. CI missed it because all `HivePlotMatrix` tests used string partitions.
- **In caplog assertions, read `record.getMessage()`, not `record.args[...]`.** `LogRecord.args` is typed `tuple | Mapping | None`, so subscripting it fails `ty` twice (`not-subscriptable` on the `None` arm, `invalid-argument-type` on the `Mapping` arm) and an ignore comment can't cover both cleanly. Asserting on the rendered `getMessage()` string (substring checks for the lazily-interpolated `%s` values) is type-clean and also verifies the message template actually rendered.
- **A code comment that cites a specific version of an optional dep's private internals reads as brittle over-engineering.** In `graph_features/__init__.py` a comment justified catching `NotImplementedError` from networkx backend dispatch with "verified against the networkx 3.6.1 `_dispatchable` source." The maintainer flagged it (2026-06-22), worried the code was "overengineered something that will only work with a specific version." The behavior is stable across versions; the pinned version and the private-symbol name only invited doubt. Fix: state the observable behavior ("networkx backend dispatch raises `NotImplementedError` when an installed, named backend doesn't implement the function") and drop the "verified against X.Y.Z source" citation and the private-internal reference.
- **Direct `ty check <file>` on `runners/` surfaces diagnostics the `make ty` gate never sees.** The project's ty config scopes the gate away from developer tooling under `runners/`, so pointing ty at those files explicitly reports errors (e.g. `call-top-callable` on a `Union[Callable, Mapping]` branch) that `make ty` ignores. Observed 2026-07-02: two such diagnostics in untouched pre-existing lines looked like regressions. Before treating them as failures to fix, run `make ty`; if it's clean and the lines pre-date the diff, leave them alone — the gate is `make ty`, not per-file invocation.
- **A deprecated-but-still-functional pandas kwarg trips this repo's `filterwarnings = error` and fails CI.** Reaching for performance/explicitness kwargs like `pd.concat(..., copy=False)` (deprecated, no-op in pandas 3+) emits a `Pandas4Warning` that passes locally with default warning filters but becomes a hard test failure under warnings-as-errors. The "optimization" buys nothing on modern pandas (copy-on-write makes `copy=False` the default behavior). Fix: just drop the deprecated kwarg. Generalizes to any soft-deprecated pandas/numpy kwarg: if it warns, it fails here. Caught only because a test exercised the multi-tag `pd.concat` branch.
