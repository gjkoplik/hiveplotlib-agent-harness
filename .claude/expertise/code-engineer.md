# Expertise: Code Engineer

Curated playbook of what this role has learned. **Not a log.** Edit existing entries when a new observation refines or supersedes them; add new entries only when truly new ground is covered; remove entries that no longer earn their place. Every entry comes from a real failure or repeated success (not invented advice), follows the entry shape (lead + body, no originating-plan citation), and stays lean (soft target ~60-90 words) per mental-model rule 11.

## Anti-patterns

- **No CHANGELOG entry for refinements to a feature debuting in the current unreleased version.** Rule 13 (and step 7 of this agent's brief) says "append CHANGELOG for user-visible work," which agents over-apply. When the feature itself is new in the top unreleased `Version X.Y.Z` block, a refinement to it (a new validator, a reworded guard message, an inference tweak, an internal refactor) is not a change to announce against any released behavior; it folds into that feature's single first-release entry. Real case (2026-05, graph-metrics on the v0.28.0 cycle): four such entries were added across sessions and the maintainer had all four removed. An entry is warranted only when behavior changes relative to a PRIOR released version; internal refactors with unchanged observable behavior belong in the plan's Implementation log, never the CHANGELOG.

## Gotchas

- **On a harness-self markdown workstream, sweep the draft for em-dashes and plan-internal identifiers before reporting.** A `SKILL.md` / agent / CLAUDE.md edit ships into consumer `.claude/`, so the no-em-dash prose rule and rule 15 (no "Workstream J", phase numbers, plan-section refs) both bind, and first-draft prose reliably introduces both. Grep for `\x{2014}` and `Workstream`; rewrite dashes as colons or commas and workstream refs as topics ("this skill's bounds conventions"). The frontmatter `description` is an easy miss, being one long line. When house style itself uses an em-dash as a delimiter (`orchestrator.md`'s `## Modes` bullets), comply in your own addition, accept the inconsistency with grandfathered siblings you must not edit, and flag it rather than replicating banned punctuation to look consistent.
- **A replace-and-sweep grep over a repo silently skips gitignored paths; scope the "clean" claim to what was actually scanned.** The Grep tool (ripgrep) respects `.gitignore`, so a repo-wide sweep never reads gitignored content (observed 2026-08-10: harness `.claude/plans/` files full of the swept phrase returned zero hits). Harmless when the skipped files aren't shipped artifacts, but the report must say "shipped/tracked files clean," not "repo clean," and expected-survivor lists in gitignored locations will show vacuous zero hits rather than confirming the survivors exist.
- **ty won't narrow `Optional[T]` across a validation block or a comprehension guard; force the narrowing at each site.** ty can't see that a `ValueError`-raising validation (or a derivation like extracting `nodes`/`edges` from `graph`) leaves an `Optional[T] = None` param non-`None`, so downstream `T`-typed calls fail type-check; add `assert nodes is not None` after the block (matching `assert sorting_variables is not None` at `hiveplot_matrix.py:1288`). It also won't propagate an `if x is not None` filter into a comprehension's element type, so `pop()`/return widens past `T`; bind with a walrus in the guard and annotate the target (`concrete: set[bool] = {v for n in names if (v := f(n)) is not None}`).
- **A decorator reading `func.__name__` trips ty (`Callable` has no `__name__`) and breaks for factory-built wrappers.** ty cannot prove an arbitrary `Callable[..., Any]` is a function, so `func.__name__` inside the wrapper fails type-check; and for wrappers built by a factory, `__name__` is the generic inner name at decoration time. Fix both at once: capture `name = getattr(func, "__name__", repr(func))` once in the decorator body (before defining the inner wrapper), and for factory products set `base.__name__` *before* applying the decorator so `functools.wraps` carries the real name through.
- **Pass `dtype=object` to `np.array(...)` when the source list mixes element types.** numpy silently promotes mixed-type lists to `<U21` (unicode), turning int `0`/`1` into strings `"0"`/`"1"` with no warning; downstream code holding the original ints (dict-key lookups, `isinstance` checks) then breaks with `KeyError`/`TypeError`. Generalizes to any `np.array([...])` from a comprehension or mixed list. CI missed it because all `HivePlotMatrix` tests used string partitions.
- **In caplog assertions, read `record.getMessage()`, not `record.args[...]`.** `LogRecord.args` is typed `tuple | Mapping | None`, so subscripting it fails `ty` twice (`not-subscriptable` on the `None` arm, `invalid-argument-type` on the `Mapping` arm) and an ignore comment can't cover both cleanly. Asserting on the rendered `getMessage()` string (substring checks for the lazily-interpolated `%s` values) is type-clean and also verifies the message template actually rendered.
- **A code comment that cites a specific version of an optional dep's private internals reads as brittle over-engineering.** In `graph_features/__init__.py` a comment justified catching `NotImplementedError` from networkx backend dispatch with "verified against the networkx 3.6.1 `_dispatchable` source." The maintainer flagged it (2026-06-22), worried the code was "overengineered something that will only work with a specific version." The behavior is stable across versions; the pinned version and the private-symbol name only invited doubt. Fix: state the observable behavior ("networkx backend dispatch raises `NotImplementedError` when an installed, named backend doesn't implement the function") and drop the "verified against X.Y.Z source" citation and the private-internal reference.
- **Direct `ty check <file>` on `runners/` surfaces diagnostics the `make ty` gate never sees.** The project's ty config scopes the gate away from developer tooling under `runners/`, so pointing ty at those files explicitly reports errors (e.g. `call-top-callable` on a `Union[Callable, Mapping]` branch) that `make ty` ignores. Observed 2026-07-02: two such diagnostics in untouched pre-existing lines looked like regressions. Before treating them as failures to fix, run `make ty`; if it's clean and the lines pre-date the diff, leave them alone — the gate is `make ty`, not per-file invocation.
- **Optional-backend imports must stay out of test-module collection scope, including `@pytest.mark.parametrize` argument lists.** Marker deselection happens after collection, so every `*_test.py` is imported even in environments lacking the extra; a parametrize list built by a helper that imports the backend (e.g. building datashader reduction cases) breaks collection there. The house pattern: parametrize over plain strings/literals, resolve the backend object inside the test body via a lazy helper, and type-annotate via `if TYPE_CHECKING: import <backend>` plus quoted annotations (satisfies ty without a runtime import). Caught 2026-07-03 building reduction-parametrized datashader tests.
- **An extra must ship whatever its advertised public surface needs, not just the headline library.** `hiveplotlib[polars]` was `["polars"]` alone, but polars defers to pyarrow for pandas conversion, so `NodeCollection.to_pandas()`, named in that same unreleased version's changelog as a new method, raised `ModuleNotFoundError: No module named 'pyarrow'` on a clean install (found 2026-08). Everything else on that install worked (construction, `frame_library`, `data` round-trip, partition variables, matplotlib viz), which is why only a single-extra CI leg could surface it. Verify by installing *only* the extra in a scratch venv and exercising the public methods that extra advertises, not just the happy-path constructor. Marker/selection mechanics for the same class of CI failure live in the test-engineer expertise file; the fix belongs in the test layout, not in a CI selector.
- **Re-deriving an aggregation's finalize step from primitive accumulators must replicate the baseline's per-divide NaN semantics.** Streamed `ds.mean` divided its accumulated sum by an all-rows `ds.count()` raster; single-shot `ds.mean(col)` divides by the column's non-NaN count, so NaN metadata silently shrank the streamed mean up to 67% while every NaN-free fixture stayed green. Two divides can legitimately need two different counts (the density correction really does use the all-rows count). Map each denominator to its exact single-shot counterpart, and sprinkle NaNs into equivalence fixtures for every column-based reduction.
- **Never pin a same-run RSS-ratio bound from estimation; measure both children first, then check the failure-mode separation.** A ratio gate's denominator child carries only ITS import stack: a baseline that never imports the rendering stack (e.g. assembly-only vs render children) makes the ratio absorb a multi-hundred-MB import delta plus dataframe-copy transients, and an estimated bound can be off by >2x (2026-07-04: a provisional 1.6 stress bound measured 3.72). Procedure: write the gate with a provisional constant, measure on the canonical host, then set the bound with stated headroom AND verify the failure mode (e.g. full materialization) still lands far past it; if the margin is thin, add a second child that embodies the failure mode's footprint directly.
- **narwhals `IntoDataFrame` belongs on input parameters only; engine-dependent returns need `Any`, and pandas keeps an isinstance fast-path at the boundary.** Annotating `.data`-style accessor RETURNS as `IntoDataFrame` made ty see `Unknown | NativeDataFrame` at every downstream pandas-idiom consumer: 259 diagnostics across src+tests in one sweep (2026-07-04, narwhals input boundary). Fix: parameters stay `IntoDataFrame`; data-dependent returns become `-> Any:  # noqa: ANN401` (house precedent: `graph_features/__init__.py:431`), and stale `ty:ignore[invalid-assignment]` comments on `.data[...]` writes go unused and must be swept. Related: route pandas frames around `nw.from_native`, not through it — narwhals raises `DuplicateError` on duplicate-column pandas frames and pandas alone honors the `Hashable` (non-str) column-name contract, so a pandas `isinstance` fast-path is what keeps "pandas behavior unchanged" literally true. When pinning that fast-path with a regression test, use a duplicate-column fixture as the proof: narwhals 2.23 actually tolerates int-named pandas columns end-to-end (measured 2026-07-04), so an int-named fixture pins the contract but would not have failed against the narwhals-wrapped code it guards.
- **A deprecated-but-still-functional pandas kwarg trips this repo's `filterwarnings = error` and fails CI.** Reaching for performance/explicitness kwargs like `pd.concat(..., copy=False)` (deprecated, no-op in pandas 3+) emits a `Pandas4Warning` that passes locally with default warning filters but becomes a hard test failure under warnings-as-errors. The "optimization" buys nothing on modern pandas (copy-on-write makes `copy=False` the default behavior). Fix: just drop the deprecated kwarg. Generalizes to any soft-deprecated pandas/numpy kwarg: if it warns, it fails here. Caught only because a test exercised the multi-tag `pd.concat` branch.
- **datashader's Dask line pipeline can stitch a spurious segment across an EMPTY interior partition; lead every partition's line frame with a `[NaN, NaN]` sentinel row.** Lazily concatenated Dask frames of NaN-separated line blocks rasterize bit-identically to pandas for trailing-empty and evenly split partitions, but an empty partition BETWEEN populated ones diverged the raster (reproduced minimally at 1 pixel; ~45 pixels on a fixture whose second partition matched no rows). A NaN first row per partition blocks any cross-boundary segment, draws nothing itself, and restored bit-exactness; note it promotes non-float metadata columns to float. Caught 2026-07-05 only because an equivalence fixture deliberately manufactured an all-non-matching partition.
- **"Bit-identical kernels" must be measured with byte views at the route's dtype; an `assert_allclose` mode test proves nothing about bitwise identity, and raster gates can absorb 1-ulp diffs anyway.** The serial and parallel numba Bézier kernels (identical bodies, both `fastmath=True`) diverge by exactly 1 ulp on ~4e-5 of float32 elements (measured 2026-07-05); the library's mode test pins only rtol=1e-10 vs numpy. Yet every exact dask-vs-pandas raster gate stayed green under a serial-forced dask route: pixel quantization absorbed the diffs, and below-threshold dask partitions vs above-threshold pandas twins already compared serial-to-parallel in green CI. Two cheap techniques: compare `out.view(np.uint8)` for NaN-safe bitwise identity, and simulate a kernel-selection change without editing source via a per-instance policy override (e.g. `hp._serial_min_points = 10**18`) to measure real gate impact before committing to a fix's equivalence story.
- **GPU memory instruments only see allocations routed through THEM: the cupy default mempool measured exactly 0 bytes across a full datashader-over-cuDF render.** cuDF allocates via RMM and datashader's CUDA aggregates via numba (cupy views over foreign memory), so a cupy-mempool "peak" for such a workload is vacuously zero, not merely small. Measure with `rmm.statistics` (enable, read `peak_bytes`): per-process and exact for everything RMM-routed, which is the whole cuDF side; device-level `memGetInfo` is whole-GPU noise (~1.3 GB of context/libraries on an otherwise idle card). Verify a pinned GPU metric registers nonzero on the real workload before building any bound or claim on it.
- **When mirroring an API onto a sibling class, check whether that class's autodoc page lists methods explicitly rather than via `:members:`.** `hiveplot.py`'s `HivePlot` renders through an `:members:` autoclass, so a new public method auto-appears in the docs; `hiveplot_matrix.py`'s `HivePlotMatrix` page (`hive_plot_matrix.rst`) uses `:no-members:` plus one hand-written `.. automethod::` per method grouped under topic headings. A mechanical broadcast (2026-07-07: `subset` + the `add_highlight`/`update_highlight`/`remove_highlight`/`highlights` family onto `HivePlotMatrix`) ships methods that never render until you add the directives; add a new topic-titled section with a same-length RST underline. This is an incidental doc edit the implementing engineer owns (the method won't appear otherwise), not a docstring rewrite that belongs to docs-engineer. The same page shape also breaks *references*: a `:py:meth:` role aimed at a sibling method with no `automethod::` line is an unresolved target, and such gaps exist (2026-08-18: four `ref.meth` warnings off one `HivePlotMatrix.unify_axes` reference, a shipped public method the page never lists). `ruff`, `ty`, and pytest are all silent on it, so run `make docs` before handing off any diff that adds a cross-reference; write the plain ``literal`` when the target isn't rendered and report the missing entry rather than quietly expanding the page.
- **Keep source comments true after the change lands and after the numbers move.** Four decaying shapes, all caught on review: migration framing ("the proven path", "exactly as before"), which describes what *used* to work; forward sequencing ("which a fused path removes later"), false the moment that path ships; magnitudes evaluated at today's defaults ("roughly 0.8 GB per 1M edges at the default 100 interpolation points"), which go silently wrong when the default moves; and prose adopted verbatim from a review suggestion, which imports the reviewer's premise unchecked (2026-08: a critic's wording shipped as a docstring saying `num_steps` takes the construction default, but it resolves from an instance attribute, so the sentence was false on any non-default instance). State the behavior plainly and give the formula (`num_edges * (num_steps + 1) * 8` bytes), not the arithmetic done for the reader. Read the resolution code before adopting suggested wording. When one claim proves wrong, grep its distinguishing phrase across `src/`, `tests/`, `runners/`, and `CHANGELOG.rst` rather than fixing only the sites the reviewer named: that same slip lived at five sites against the two cited, and the sweep that missed `runners/` left the stale magnitudes there for another week. Volume is itself a flag: eight constants once carried 90 comment lines, cut to 50.
- **A remedy you name has to work in every state that reaches the text, whether that text is a warning, a `.. note::`, or a brand-new method's docstring lede.** Five sites in one hiveplotlib sprint pointed the user at a call that raises for lazy (Dask) edge data (`construct_curves()` raises `TypeError` on a `LazyEdgeSubset`): three warnings, one `.. note::` whose own paragraph had enumerated that state three lines above, and a fifth that shipped *after* the standing check ("does this method raise for lazy edge data?") was adopted, because the check got applied to warning messages and not to the new method's docstring. Before shipping text that names a method, enumerate the states reaching it and branch where they differ (`viz/input_checks.py`'s lazy/eager split is the house pattern); the site usually already computes the discriminator. Corollaries: if a public method can raise, its docstring says so, and the population to fix is the call graph, not the sites a review happened to name; scope granularity follows the method's blast radius, not the sentence's subject (`construct_curves` iterates *every* ids-only subset, so it raises on a mixed eager/lazy instance and the correct scope is "on eager edge data" for the whole hive plot, never for one subset); and a flag any loop iteration can set cannot support a global "was not applied", so scope it ("in at least one subset ... not applied there"), which also avoids a branch needing a new test under a 100% gate.
- **A class with no code and no tests for a state can still reach that state by composition; probe before writing a docstring clause about it.** `hiveplot_matrix.py` contains zero occurrences of "lazy" or "Dask" and `tests/dask_test.py` never mentions `HivePlotMatrix`, which reads as "the matrix does not do lazy edge data." A 12-line probe said otherwise: `HivePlotMatrix.from_partition` over an `Edges` holding a Dask frame builds fine, every populated cell holds `LazyEdgeSubset` ids-only records, and the forwarded `persist_curves` stays `True` while nothing persists. Grep absence is evidence about the file, not about the behavior. Run the throwaway script before broadcasting a state-based clause to a sibling class.
- **A `from_partition` matrix has heterogeneous per-cell axes; a single axis-pair edge selection is not valid on every panel.** Diagonal cells carry `["A", "A_repeat"]` and off-diagonals `["A", "B", collapsed-"Other"]`, so a broadcast `edges=("A", "B")` raises `InvalidAxisNameError` on the diagonal "A" panel. `from_variable_sweep` (fixed `partition_variable`) gives identically-axed panels where an axis pair is universal. When testing a broadcast that forwards an axis-pair selection to every cell, use a variable-sweep fixture, not a partition fixture; node-ID / mask / expression selections broadcast fine on either.
- **A CHANGELOG entry's four-line cap is a wrap measurement, not a line count; budget ~440 characters, not 480.** `audit.sh changelog-cap` joins an entry's physical lines, re-wraps the result at 120, and fails past four lines, so a bullet dense with `:py:class:` / `:py:meth:` roles loses 40+ characters to bad break points (measured 2026-08: 474 joined characters still wrapped to five lines, while 440 fit). Draft against the audit, or a throwaway `textwrap.wrap` probe, rather than against how the file looks; when trimming, an enumeration of names (three builder method names cost 62 characters) is cheaper to lose than a clause carrying a fact, and a fact already stated in a neighboring entry is cheaper still.
