# Expertise: Orchestrator

Curated playbook of what this role has learned. **Not a log.** Edit existing entries when a new observation refines or supersedes them; add new entries only when truly new ground is covered; remove entries that no longer earn their place. Every entry comes from a real failure or repeated success (not invented advice), follows the entry shape (lead + body, no originating-plan citation), and stays lean (soft target ~60-90 words) per mental-model rule 11.

## Patterns to reach for

- **Plans for the harness itself live in the harness.** When a plan's consumer is the agent-harness submodule (work changing harness rules, agents, templates, or skills), it lives at `agent-harness/.claude/plans/<topic>.md` (gitignored), not the wiki at `wiki/wiki/plans/`. The repo being modified owns the plan; the harness has no wiki dependency.
- **A harness-self research run lands inside the harness repo, and not via research-liaison.** Two traps. (1) The wiki route was tried and reversed: the Pocock run's `wiki/wiki/analyses/` page was deleted as topically orphaned, and that run's adversary had flagged the tracked-page-in-the-harness option as unconsidered. (2) `.claude/plans/` is gitignored, so a plan-only landing is not durable. Propose a tracked harness path, and name the lander: research-liaison's producer path is wiki-bound (frontmatter, wikilinks, `log.md` append) and stops on harness-self paths, so the dispatching session lands the page itself against the same five-slot schema.
- **When post-impl critic findings or scope-changing user asks arrive mid-flight, your job is `amend-plan` mode.** Triage each delta into Added workstream / In-scope tweak / Deferred follow-up, edit the plan's "Plan amendments" section in place, and return a dispatch recommendation. The dispatching session routes the trigger to you under mental-model rule 14; the user doesn't scope emergent work themselves. The role is "planning specialist," not "single-shot planner at task start."
- **When introducing multiple new "modes" for one agent, check whether each candidate has independent function or is a parameter switch on an existing mode.** A real mode differs in inputs, outputs, or decision shape (`initial-plan` produces a new file; `amend-plan` reads an existing file and edits its amendments section). A parameter switch reuses an existing mode's function with a different consumer or path; collapse those into the existing mode rather than coining a sibling that multiplies the surface dispatching sessions must remember.
- **After you collapse N modes into N-1, the dispatch recommendation must explicitly direct the code-engineer to sweep for residual mentions of the dropped name across the agent definition.** The Modes section closes cleanly (N-1 names), but the dropped name typically survives in Output descriptions, parenthetical lists, example invocations, and error messages, since those describe behavior rather than enumerate modes. State the sweep direction in the recommendation so the code-engineer doesn't infer it.
- **Every new `amend-plan` workstream with user-facing API surface needs an `### API Critic — post-implementation review` placeholder, written when the workstream brief is written.** Without it, qa-engineer's "Critic post-impl reviews" audit fires `must-fix` and the amend-plan cycle repeats just to add it. Mechanical check: when writing `## Workstream <X>: <title>` for an API workstream, in the same edit append the `### API Critic — post-implementation review\n\nPending — invoke api-critic in post-implementation mode after Workstream <X> ships.` block (or, if the Implementation summary doesn't exist yet, queue it in the workstream's `Done when`).
- **A sub-agent surface-back trigger is by construction a re-triage signal, and the re-triage almost always upgrades the bucket.** When an in-scope tweak carries a "surface back if the fix needs source-side changes" contract and that trigger fires, the investigation has falsified the original bucket. Don't re-file the same delta under the same bucket with an "updated dispatch sequence" footnote; that hides the bad scoping and lets the new fix skip the heavier bucket's verification gates. If the re-triaged dispatch spans more than one specialist, it's a workstream — keep the original tweak entry as historical record with a closing "upgraded to Workstream <X>" pointer; supersede its `Done when` / `Out of scope`, don't amend in place. Real case: a `conf.py`-only tweak that investigation showed needed source changes across two files, upgraded to a workstream.
- **When a task brief suggests a specific mental-model rule number OR workstream letter, verify the slot is free against the current canonical surface before locking it in.** Both sequences are append-only, so a brief written before the latest cycle can name a taken slot. Mechanical checks: for rules, grep the mental-model SKILL.md for `### <N>\.` headings and pick the next free integer; for workstreams, grep the plan for both `## Workstream <X>` and `### Added workstream <X>` (both shapes coexist after multi-cycle amend-plan) and pick the next free letter.
- **A user-endorsed carve-out only pre-covers a later `must-fix` if both are on the *same axis*.** A carve-out endorsing one dimension (say, that a dataset may carry two partition variables) doesn't cover a finding on a different dimension touching the same data, like a lead-in-vs-body dataset contradiction where the prose promises a section is on one dataset but its code uses another. Don't wave it off as "already endorsed." Triage test: name the axis the carve-out endorsed and the axis the finding flags; if they differ, it's a separate must-fix, and the amendment should say so.
- **When a lead-in mis-describes a section's dataset but the section's *code* is correct, relocate the section rather than re-cast it, and verify by tracing variable lineage by cell id, not index.** Moving the section into the run that matches its data (option a) beats rewriting working code to chase the prose (option b), which churns a correct demo and risks figure/test fallout. Confirm option a is clean by tracing the governing variable's assignments by stable cell id (e.g. all top-level `G =` cells), not index, since post-edit notebooks renumber. Also re-scan for an *over-absolute* lead-in (a "remaining sections" claim that overreaches a later section legitimately returning to the original dataset) and fold that prose-scoping into the same fix.
- **Vocabulary refactors that touch test-asserted strings are added workstreams, not in-scope tweaks — even when the underlying change is "one word."** The triage line is not "is the rewording small?" but "how many specialists does the change span, and does any touch a contract surface that needs its own done-when?" A refactor whose locked strings appear in `match=re.escape(...)` assertions spans code-engineer (source rewording), test-engineer (assertion update), docs-engineer (cross-file sweep), notebook-author (prose sweep), and qa-engineer (full-suite verification) — five specialists co-touching one contract is the workstream shape. The in-scope-tweak shape fits when a single specialist owns the change against a surface a prior workstream already owns. Verify the "test-asserted" premise by grepping `tests/` for the locked strings before sizing: a 2026-06 brief assumed import-guard messages were test-asserted, but all eight guards were `# pragma: no cover` with zero string assertions, shrinking the expected test work to verification-only.
- **When a brief proposes "extend an existing rule OR add a sibling rule," check whether the existing rule has substructure that accommodates extension before minting a sibling.** Rules with lettered substructure (rule 16 has (a) trigger taxonomy, (b) justification, (c) anti-action enumeration, (d) correct action, (e) relationship) extend cleanly: new trigger → (a), new anti-action → (c), rest unchanged. A sibling duplicates (b)/(c)/(d)/(e) scaffolding and dilutes the cross-reference surface (every agent definition citing the old rule must now decide whether to cite the sibling too). The bar for a sibling is real independent function: trigger outside the existing taxonomy, anti-action outside the existing enumeration, or a genuinely different correct-action shape.

- **The feasibility audit must trace the install and import paths, not just the API/call path.** Tracing knobs to documented constructor parameters misses two failure modes a plan pays for later. (1) *Install-closure drag-in:* an extra silently pulls a heavy transitive dep (hiveplotlib's `[networkx]` extra pulls scipy, +14.9 MB, which a Pyodide/WASM plan had excluded for payload); check each extra's closure against the plan's exclusion list and write the safe install form (`networkx` directly, never the extra) into the done-when. (2) *Import-time execution:* a module added to a star-importing package runs at import (`hiveplotlib/datasets/__init__.py` star-imports every module, so a module-level networkx guard copied from `converters.py` breaks `import hiveplotlib.datasets` for non-networkx users, invisible from the function's API trace); require a function-level import with the helpful-extra error and say why the sibling's module-level pattern doesn't transfer.

- **An amendment owes the whole plan body, not just the workstream sections the brief names.** Amendments tend to land brief + done-whens and stop, leaving two whole-plan holes. (1) *Audit sections:* each added workstream that rewrites existing surfaces has replace-and-sweep hits, and qa's rule-2 sweep has nothing to grep unless you extend "Patterns this replaces" with them or state "net new" per surface (an Osmani-plan delta shipped three added workstreams with zero new entries, 2026-07-03). (2) *Residual mentions of dropped items:* a helper superseded or dropped by the amendment also lives in Goal, "Patterns this replaces," "Naming audit," and "Holdouts" (a 2026-06-11 ASV amendment dropping `time_median_of_n` left it in four body sections outside the named workstreams, reading as still-planned). Grep the whole plan for the changed/dropped name before closing the amendment.

- **When the maintainer knowingly skips the grill, the adversary's planning challenge reroutes to amend-plan for explicit disposition; the skip itself is recorded in `## Alignment (grill)`.** Normally the maintainer fights the planning challenge in the grill and the orchestrator never disposes it. With the grill skipped there is no fight, so a dangling challenge would leave the adversary's post-impl reconcile step nothing to read. Dispose every item (adopt / rule out, with the delta each adoption lands), and replace the alignment placeholder with the skip record so the gate reads as a decision, not an omission. Async variant (2026-08-08): when the maintainer is absent entirely, the dispatching session may adopt conservative dispositions under the standing autonomous-run policy — mark each explicitly as a dispatch-session disposition subject to maintainer re-litigation at review, and leave genuinely maintainer-owned calls (e.g. a destination choice) tagged open rather than silently adopting a default.

- **When a must-fix resolves by removing a surface element, sweep the critic's remaining findings for ones the removal also resolves or moots, and annotate them in the same amendment.** Dropping one metric from a menu simultaneously mooted a convergence-risk finding and partially resolved a label-consistency finding; left unannotated, those findings read as still-open and trigger redundant amend-plan cycles. Resolution-by-removal cascades; resolution-by-configuration usually doesn't.

- **When science/figure iteration outpaces a busy release branch, split it into a scratch story repo with an explicit ownership boundary.** Twice in June 2026 (bioinformatics examples; same-stats WS-0) the right amendment moved narrative, figure design, and parameter choices into a separate committable repo gating the library workstreams, while the plan kept API, tests, tutorial port, and docs. Write the boundary as binding in the workstream brief, and state that API surfaces (signatures, keys, attribute names) stay with the plan's API gate so the story repo can't accrete design decisions.

- **Write API usage examples, and any brief-supplied `file:line` citation, against the working branch rather than the surface you remember or were handed.** Both directions have cost a cycle: a plan headlined the old two-step converter idiom on a branch that had just shipped `HivePlot(graph=...)`, and a brief cited a `twine upload -u $PYPI_USERNAME` line the in-flight branch had already replaced with OIDC publishing. Before finalizing, Read the lines the plan will cite, record superseded citations instead of copying them forward, and name a shipped test or notebook per snippet as its runnability witness (a witness-less snippet is where invented parameters hide). Extends to sibling-repo facts a liaison brief hands over: verify against the named local checkout at plan time, since a stale version there can change the proposed integration seam.

- **An edit instruction targeting another *active* plan's text rots fastest; re-verify the live target text when disposing or dispatching it, and anchor the instruction on a grep-able phrase, not a line ref.** Active plans self-correct: a WS instruction to fix the scaling plan's "only known read site" claim went stale when that plan corrected the claim itself three days before execution (adversary must-fix, 2026-07-06). At amend/dispatch time, Read the target plan, restate the instruction against its current text, and when the target workstream already shipped, mark the appended line as a post-ship addendum so it can't read as a retroactive member of a shipped verified list. When the disposition is itself a small plan edit, apply it in the amend pass (plans are orchestrator surface) instead of queueing it for a fix dispatch; every handoff is another rot window (same bullet, second lesson, 2026-07-06).

- **When appending an amendment by anchoring an Edit on the next section heading, the bare heading string can match a backtick-quoted cross-reference earlier in the file — splicing the amendment mid-sentence.** An Amendment-5 insertion anchored on `## Holdouts` landed inside a "(see `## Holdouts`)" cross-reference in "Patterns this replaces", corrupting both sections until the adversary caught it a workstream later (2026-07-03). Anchor on the preceding amendment's closing sentence plus the heading, and after any structural plan edit, Grep the heading offsets and ranged-Read the seams.

- **When speccing an unconditional tool run with a report-field grammar and a pass gate, enumerate every reachable case — consumers *and* diff shapes — and give each an honest value.** A dependency-audit run shipped a grammar with no value a tooling-less consumer could emit (agent-harness itself, so the authoring plan's own qa couldn't pass); the same plan's perf check then repeated the failure on the other axis: its `n/a` honesty clause covered only docstring/comment-only diffs, leaving notebook-only/tests-only/docs-only/CI-only diffs (the most common shapes) with no honest value even on a tooling-equipped consumer (two adversary must-fixes, 2026-07-03). Check every known consumer (harness-self included, with the consumer-resolution clause) and every common diff shape against the grammar before shipping the field.

- **When an amendment changes an output grammar or field shape, sweep the plan's unshipped workstreams for done-whens that assert against the old shape.** Amendment 8 split qa's `Security audit:` field into tool-run + checklist components; WS-D's pre-proceed done-when still checked "field is not `n/a`", which the new grammar satisfies vacuously (the tool-run component always carries a result), deadening the backstop it enforced (2026-07-03). Line-number anchors get re-pointed by habit; *semantic* assertions against the changed surface are the ones that silently rot.

- **When a plan replaces a harness-wide bound or convention statement, grep the consumer repo's *tracked* files too, not just the harness and its synced `.claude/` copies.** Consumer CLAUDE.md trip-wires restate harness bounds in their own words (hiveplotlib's research trip-wire restated the research-track agent cap), and a harness-scoped grep misses them while `make sync` never fixes them (they are tracked originals, not copies). List the consumer-side hits as first-class sweep targets with their own edit, and note their CHANGELOG treatment (dev-loop doc edits usually don't earn a consumer entry).

- **When a brief says lost text is "recoverable from git," verify before encoding that path in the amendment — an in-place auto-fix of an *uncommitted* file destroys the only copy.** qa's cap compression rewrote a maintainer-written CHANGELOG entry that was never committed or staged; `git diff` then showed only the compressed version and the stash predated the entry, so the assumed `git diff` recovery was empty (2026-07-03). Check HEAD, index, and stash; when git has nothing, route recovery through the transcript or the maintainer, and require the verbatim text in the dispatch brief with a halt-if-absent clause rather than letting the implementer reconstruct.

- **When a concurrent-edit constraint bars cascading a supersession into the normative sentences, the amendment must carry the full replacement language, name each superseded sentence by section, and queue the cascade explicitly.** An amend-plan pass run while a code-engineer holds the same plan file open may be scoped to "amendments + status lines only"; recording only "language corrected, see discussion" would recreate the uncascaded-drift failure this plan already paid for. Make the amendment self-sufficiently normative (verbatim new language, located supersessions, cascade-owed note) so the plan-as-shared-memory is correct even before the cascade lands (2026-07-03, WS2 exactness-set correction).

- **When a done-when pins a measurement instrument for a hard gate, pin the isolation scope too: what the number must be isolated *from*, including other phases of the same run.** A GPU-VRAM gate pinned "per-process peak (exact)" but not per-route isolation; the test ran two routes back-to-back in one process against a monotone statistics counter, so the second route's figure absorbed the first's epoch (streamed read as exactly 2.0007× single-shot) and the gate discharged on a contaminated split (adversary caught it post-impl, 2026-07-05). Monotone instruments (RMM statistics, peak-RSS) inflate every phase after the first; require fresh scopes or isolated processes per claimed number.

- **A constraint recorded in "Prior ADRs / design docs" is commentary until cascaded into the workstream specs it names.** research-liaison's pre-task findings can carry normative sentences ("Workstream C/D prose must not imply X"); the specs don't inherit them automatically, and a plan shipped with the contradiction intact (2026-07-06, unify-axes: Prior-ADRs said per-plot `unify_axes=True` gives no shared frame across different-data instances, while "Patterns this replaces" still said "point at `unify_axes` first" for a cross-plot use case). At plan write or amend, diff each liaison constraint against the guidance sections; disposing such a flag is an in-scope tweak that operationalizes the recorded constraint.

- **A post-impl `must-fix` whose fix belongs to a not-yet-shipped workstream routes as an In-scope tweak to *that* workstream's done-whens, not a touch of the shipped workstream that surfaced it.** Twice on the research-track plan (2026-07-03), the adversary's post-impl on a shipped workstream (J, then L) found the shipped diff correct but named a gap sited upstream in an unbuilt sibling (J's model was under-specified; L's landing had no yield judgment because the summary shape G and synth M carry it). The tell: the shipped critic block itself says "belongs to X/Y, not this workstream." Amend the upstream workstream's done-whens so it ships correct the first time; state in the amendment that the shipped workstream is preserved intact and why (it correctly formats/consumes what it is handed). Don't reopen the shipped surface to compensate for an unbuilt one.

- **When a plan ports code or narrative from a scratch/story repo, pin the port source to an immutable committed ref and port from generators, not built outputs.** Require the maintainer to commit pending story-repo edits as part of the go signal, record the hash in the Implementation log, and treat a dirty port-relevant tree as a halt. Built artifacts silently lag their builders: a story notebook was missing the caveat paragraph its builder script already carried (2026-07-06); the builder, not the ipynb, was the narrative source of truth.

- **Before amending a surface a prior post-impl critic already walked, grep that critic's own concerns and their disposition; an adjacent remedy was often already rejected.** A 2026-08-13 amendment adopted a "geometry silently ignored" warning on a surface whose WS3 api-critic pass had proposed a warning on the *neighboring* trigger and had it rejected as too narrow a population. Left unsaid, the amendment reads as a silent reversal. Name which trigger you do and do not reverse. Second half: **any enumeration a critic or brief hands you is a floor, not a census** — re-derive it by grepping the forwarded name across the call graph before writing the sweep. A doc clause a prior disposition adopted landed in three sites, not the one named; a 2026-08-17 api-critic take named five of six `HivePlot(...)` forward sites in the matrix builders (a second branch per cell type), one of two mirrored docstring twins, and seven of ten callers of the rebuild entry point.
- **Every disposition resting on "X is unreachable / inert" decays the moment the revision changes reachability; re-derive each one instead of carrying it forward, and sweep the *sibling* parameters on the same call.** In one 2026-08-13 revision, settling "an explicit value rebuilds from stored ids" simultaneously (a) flipped a "P2CP not supported, warn" decision to supported-and-tested, since its whole premise was that the rebuild route was unreachable from that class, and (b) dissolved the planned warning, which had no trigger left. But only after checking the *other* parameter on the same signature: keying the rebuild on the named parameter alone would have left a sibling geometry dict still silently inert. Enumerate the surface's parameters and every "not supported" / "cannot take effect" claim, and re-answer each against the new semantics.

- **When a new parameter would duplicate an existing library default, prefer an `X | None = None` sentinel resolving to the existing source of truth over restating the literal.** A render-time `num_steps` typed `int = 100` would have added two new sites to a sibling plan's in-flight default-change sweep; typed `int | None = None`, resolving to the instance's declared value and otherwise falling through to the callee's signature default, it added none and inherits the new default for free. Check the active-plan list for a pending change to any default you are about to restate.

- **When a plan adopts "rebuild it transiently instead of reading the stored artifact," audit the *constructing* call sites' argument conventions, not just the shared helper's signature.** A 2026-08-13 rebuild semantic looked exactly equivalent through the shared geometry helper, but the method that persisted the artifact anchored both stored directions on its own argument order while the helper defaults to the subset's own order (a source comment said "order-symmetric mathematically but not always bit-for-bit"). The rebuild would have matched modulo a 360-degree rotation, against a plan whose gate is bit-exact rasters. Fix in the plan: record the convention with the artifact, and name which twin the equivalence gate compares against.
- **Before triaging "drop a variant/member" of a seeded family as a small tweak, read how per-item rng streams derive.** Position-indexed seeding (`[seed, NAMES.index(name)]`) makes membership load-bearing: dropping one item renumbers every later stream, changes their outputs, and invalidates anything signed off against the old renders. If seeds are positional, dropping is a breaking change with figure fallout, and ship-but-document usually beats drop; name that cost in the amendment rather than treating removal as cleanup (2026-07-06).

- **A plan adding a "skip this construction step" flag owes an audit of every existing gate keyed on the artifact being skipped.** Two failure shapes, both cheap to find and expensive to miss: a gate that *warns* on the skipped artifact fires spuriously on the new happy path, which under `filterwarnings = error` is a suite-wide failure; a gate that silently no-ops is a live defect the flag turns from rare into ordinary. On the 2026-08-17 `persist_curves` audit, one existence check keyed on stored tags was clean, while `update_edges` and both `to_json` implementations keyed theirs on the skipped artifact (two shipped defects, folded into the workstream). Enumerate the artifact's readers before writing the done-when.

- **`amend-plan`'s feasibility audit fires on "new entry point or new attribute reads," which misses an amendment adding a *setting* to an existing object; run it anyway, and run it before choosing the surface, not after.** `persist_curves` was settled as a constructor-local flag and only then found to be silently undone by seven public `HivePlot` mutators that default to rebuild, costing four adversary rounds on an already-agreed shape (2026-08-17/18). The durability half is api-critic's rebuild-caller grep; the half nobody owned is reachability, and it is cheaper: write the literal code a user types to get each benefit the amendment claims, starting from nothing. If it cannot be written without a class the maintainer does not support, that is the finding, and it surfaces in five seconds at line one.

## Anti-patterns

- **Don't pre-decide which agent runs an amendment workstream.** When triaging an Added workstream into "Plan amendments," name the files and the done-when; do **not** name the specialist who runs it. Dispatch is the dispatching session's call; the recommended sequence in the conversation report is a guide, not an assignment.
