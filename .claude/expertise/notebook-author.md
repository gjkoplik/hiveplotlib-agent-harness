# Expertise: Notebook Author

Curated playbook of what this role has learned. **Not a log.** Edit existing entries when a new observation refines or supersedes them; add new entries only when truly new ground is covered; remove entries that no longer earn their place. Every entry comes from a real failure or repeated success (not invented advice), follows the entry shape (lead + body, no originating-plan citation), and stays lean (soft target ~60-90 words) per mental-model rule 11.

## Patterns to reach for

_Approaches that work in this role, with the trigger that suggests reaching for each._

- **When a workstream consolidates two API surfaces into one, re-sweep prose in the same pass as the call sites.** Dual-shape framing ("available both when X and Y", "regardless of whether you pass A or B", "If you are starting from a Z rather than a W...") earns its keep only during the dual-surface period; after consolidation it's dead weight, so pick one canonical form per cell and let the API docs handle cross-shape documentation. It slips back in because the easiest local edit during a call-site flip is to swap the API call and keep the surrounding prose scaffolding. Trigger: any consolidation workstream; don't wait for a user to flag it.
- **When the plan's framing of an algorithm's behavior is approximately-but-not-exactly right, bend the prose to match the API behavior, not the API call to match the prose.** Two responses to a mismatch: (a) fudge a kwarg (e.g. `resolution=0.5` to force the plan's promised 2-community story) or (b) keep defaults and recast the markdown around what the algorithm actually produces. Pick (b): default-`resolution` Louvain finds 4 communities on Karate Club (not 2, though each lives mostly within one club), and the cell's pedagogical point ("integer labels go directly into `partition_variable`") survives the honest 4-community story as well as a tidy 2-community one. Only halt under rule 9 if the actual behavior defeats the pedagogical point.

- **On a markdown-only notebook edit, verify the prose's API claims in a `/tmp` script and leave the stored outputs alone.** Re-executing to satisfy "executes end to end" rewrites every output cell (base64 images included), turning a four-line prose diff into a whole-file one on the maintainer's slowest review surface. Instead run the exact calls the new prose recommends (warnings-as-errors on, `Agg` backend) against the notebook's own data, then re-validate the `.ipynb` with a strict `json.load`. Trigger: any targeted prose fix to an existing, already-executed notebook.

## Anti-patterns

_Specific failure modes seen in this role, each tied to a real incident or repeated mistake. Empty until earned._

- **Standing bookkeeping defaults (CHANGELOG, Implementation log) lose to a dispatch brief's edit-ONLY file list.** Authoring the polars gallery page (2026-07-04), the brief enumerated exactly three editable paths; the role's rule-13 reflex still added a CHANGELOG entry, which then had to be hand-reverted in a working tree full of other agents' uncommitted edits (safe only because the edit was just made and the exact prior text restored). Check every planned write against the enumerated list before touching the file; hand excluded entries back in the report as ready-to-paste text. Trigger: any dispatch brief with an explicit "edit ONLY" constraint.

## Gotchas

_Surprises not obvious from reading the code, docs, or other agents' definitions._

- **`HivePlotMatrix` doesn't expose `.nodes` / `.edges` at the top level; reach for them through any populated cell.** Every cell carries the same underlying `NodeCollection` and `Edges` (partition slicing happens per-cell at plot time, not at storage time), so when swapping `HivePlot` → `HivePlotMatrix.from_partition`, grep surrounding cells for `<varname>.nodes.data` / `<varname>.edges.data` and reroute each through an arbitrary populated cell (e.g. `hpm[0, 0]`, the canonical diagonal). Add a one-line "every cell carries the same underlying nodes" comment so the reader isn't lost in the indirection. Trigger: any HPM swap with surrounding cells inspecting the source data.
- **Dispatching two backend-routed metrics against the same networkx graph object fires a networkx cache `UserWarning` that renders as a red stderr box in docs.** The first dispatched call converts and caches the graph (`G.__networkx_cache__`); the second dispatch reusing that cache warns. `HivePlot` rebuilds its internal graph per metrics call, so construction-then-`compute_graph_metrics()` is clean, but one construction requesting node *and* edge dispatched metrics, or two standalone `compute_graph_metrics(G, ...)` calls each dispatching on the same `G`, warns. Keep at most one dispatching metric per graph object per call; dry-run cells with stderr captured before assembling the notebook. Also: nx-parallel 0.4 prints a stray `n_jobs=` line under the `backend_priority` route (not under explicit `backend=`), a reason to show the env-var route as markdown-only code blocks.
- **A constructive `HivePlot` demo that sorts an axis by a non-numeric column breaks at construction, but the failure hides behind any sibling error-demo that raises first.** Axis sorting coerces the sort variable to float, so `sorting_variables="<string col>"` (e.g. Karate Club's `club`, values `'Mr. Hi'`/`'Officer'`) throws `could not convert string to float` the moment a plot actually builds. `try/except` break-case cells using the same string sort run clean because their `ValueError` (a bad-kwarg or graph-type conflict) fires before sorting is reached, so copying their kwargs into a cell that is *meant to succeed* silently inherits the landmine. Sort the constructive cell by a numeric column on the raw nodes, preferring a metric the cell already computes (e.g. `in_degree`) over `unique_id` when the notebook is metrics-themed, so the axis stays on-topic. Verified examples in a plan may only ever raise, so they won't have exercised this; the trigger is any new cell that constructs and renders/augments rather than catching an error.
- **Setting the same kwarg (e.g. `color`) on both `all_edge_kwargs` and a more-specific tier (`repeat_edge_kwargs` / `non_repeat_edge_kwargs`) fires a hierarchy-overlap `UserWarning` that fails warnings-as-errors CI.** The two-tone repeat/non-repeat pattern (gray within-group, saturated between-group) is correct, but encode it as two *disjoint* tiers: put the between-group color on `non_repeat_edge_kwargs` and the within-group color on `repeat_edge_kwargs`, leaving `all_edge_kwargs` for color-free settings (`alpha`, `linewidth`). Putting one color on `all_edge_kwargs` and another on `repeat_edge_kwargs` overlaps (all covers repeat), so the hierarchy check warns even though the result looks right. Trigger: any repeat-axis figure where you reach for a second edge color.
- **The committed `.ipynb` is the artifact; validate it strictly, never a lenient parse or a paraphrased dry-run.** Two misses share this root. (1) Structural: a raw newline inside a cell's `source` string (instead of escaped `\n`) makes invalid JSON that lenient readers (nbformat, `ConvertFrom-Json`) accept but the strict Sphinx build turns into cascading docutils `Unexpected indentation` errors and a dropped H1, surfacing only as a downstream `toc.no_title` warning; after any raw `.ipynb` edit, validate with `python -c "import json; json.load(open(p))"`. (2) Runtime: a headless Agg dry-run of paraphrased blocks skips what only the committed notebook does: an output-only `.to_dict()` on unhashable list-groups (`TypeError`, coerce to `tuple` first) or a warning from a kwarg present in the final cell but absent from the dry-run. Execute the actual `.ipynb` end to end (`nbconvert --execute`) and scan every cell's outputs for `output_type=="error"` and `stream`/`stderr` (warnings live there; nbconvert does not fail on them).
- **To make axes comparable across hive plots, pin explicit ranges through the public API, not by mutating `Axis` internals or inferring from data.** Building apples-to-apples passing plots (2026-06-25), the figure code reached into low-level axis internals to set ranges; the maintainer pushed back ("why are you doing it this low-level way... at least do a `hive_plot.update_axes` call. This just feels dirty"). Two coupled fixes: set `vmin`/`vmax` in the `HivePlot` constructor (or call `update_axes`), and pin them to the known domain, not the observed data range, so an axis whose values land only in the first 10m of a 30m pitch third still spans the full 30m. Trigger: any figure where axes must be comparable across plots.
- **A local `[text](other.ipynb)` cross-link to a notebook absent from the current build tree fails `make docs`.** nbsphinx resolves local `.ipynb` links at build time and emits `WARNING: File not found: 'notebooks/other.ipynb'`; under warnings-as-errors that fails the build (observed 2026-07-06, SBM gallery example linking `finding_a_partition.ipynb`, which lived only on an unmerged MR). This is the graceful-cross-links rule with build-failure teeth: a cross-link between notebooks on different unmerged branches must be deferred until both endpoints live in the same tree, not switched to an absolute `stable` URL (breaks the corpus's local-link convention and points at a release that won't contain the target yet). Trigger: any notebook cross-link whose target isn't already committed in this tree.
- **A markdown link whose label is wrapped in backticks silently fails to render as a link under nbsphinx/myst, leaving a literal code span plus the bare URL as visible text.** Authoring the gotchas page (2026-07-06), `[`+"`"+`ClassName.attr`+"`"+`](../autodoc/...#anchor)` rendered as `` `ClassName.attr` `` followed by `<../autodoc/...>` as plain text; the build stayed green (no warning) so only inspecting the built HTML caught it. The corpus autodoc-link idiom uses a *plain-text* label (`[Node Metric Table](../autodoc/hive_plots/graph_features.rst#node-metric-table)`), never backticks inside the brackets. Fix: plain-text label. Deep-linking into an autodoc page works via a relative `.rst#anchor` path (nbsphinx rewrites `.rst`→`.html`); the anchor may be a section slug OR a Sphinx domain-object id (`#hiveplotlib.BaseHivePlot.edge_coverage`) as long as that `id` exists in the target HTML. Trigger: any notebook markdown link pointing into the autodoc API pages; always grep the built HTML for the resolved `href` before reporting done, since a broken one is silent.
